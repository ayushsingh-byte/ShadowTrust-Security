Architecture

One stack. Every hop accounted for.

Honeypot sensors write JSON logs, a local collector tails them into MariaDB, and a rule-based detection engine turns events into incidents that stream live to the console. Malware, APK, Splunk and lab services run alongside. One Docker Compose command deploys all of it.

BackendPython 3.11, FastAPI, Uvicorn
StorageMariaDB 11, phpMyAdmin
ConsoleStatic pages behind Nginx 1.25
Live dataServer-Sent Events
DeployDocker Compose, 12 core containers

02 Data flow

How an attack moves through the platform.

From first contact with a honeypot to a finished report. Every step below runs without anyone clicking anything.

Honeypot captureStep 1 of 8
  1. 1

    Honeypot capture

    Attackers interact with Cowrie (SSH and Telnet login attempts and shell), Dionaea (malware uploads) or Honeytrap (probes on other ports). Every keystroke, credential attempt and uploaded file is recorded. Each sensor appends newline-delimited JSON to its own log file, which is the only channel out of the isolated honeynet network.

    honeynet_edge
  2. 2

    Telemetry ingestion

    The FastAPI backend watches the sensor logs with inotify and tails them from stored byte offsets, so each line is read exactly once. Events are normalised, written to MariaDB and published on an internal event bus that feeds the Server-Sent Events stream.

    services/telemetry/collector.py
  3. 3

    Classification and enrichment

    Each event is classified by rule-based heuristics into categories such as SQL injection, XSS, brute force, remote code execution and path traversal. GeoIP adds country, ASN and city, a risk score from 0 to 100 is computed, and MITRE ATT&CK techniques are attached.

    log_categorizer · mitre.map_to_mitre
  4. 4

    Session correlation

    A background session engine runs every 60 seconds and groups raw events by source, timing and protocol into attacker sessions. It rebuilds timelines, notes persistence attempts and builds the behavioral profiles used by the Behavior and Geo pages.

    services/session_engine.py
  5. 5

    Detections and incidents

    Six YAML rules watch the stream. When one matches, the engine opens or updates an incident with severity, evidence and an ordered timeline. Eight validation scenarios can replay attacks to prove each rule still fires.

    backend/detections · backend/scenarios
  6. 6

    Malware pipeline

    Captured files are hashed and statically analysed, scanned by ClamAV and YARA, optionally detonated in a CAPE sandbox, and searched for credentials and API keys. Results are stored and linked to the attacker session.

    static_analyzer · av_scanner · yara_scanner · sandbox_engine
  7. 7

    Lab machines

    Kali and analysis desktops run as local containers and open in the browser through Apache Guacamole. With AWS configured, analysts can also launch isolated EC2 instances through /api/v1/vm/launch, reached through Systems Manager without SSH keys and terminated when the session ends.

    labnet · aws_orchestrator.py
  8. 8

    Console and reports

    Nginx serves the static console on port 5500 and proxies /api to the backend, so browsers never make cross-origin calls. Live events arrive over SSE. Incidents, evidence and PDF reports are all generated from the same MariaDB data.

    frontend/nginx.conf

04 Deployment

What docker compose up starts.

Read straight from docker-compose.yml. Host ports are defaults and can be changed in .env.

honeynet_edge

Attacker-facing. Sensors only. No service belongs to both this network and the application network, so nothing here can reach the backend.

  • cowriecowrie/cowrie2222, 2223
  • dionaeadinotools/dionaea445, 2121, 1433
  • honeytraphoneytrap/honeytrap8022, 8023

honeynet_app

Backend, console, database and the analysis engines. The backend reads sensor logs from disk, not over the network.
