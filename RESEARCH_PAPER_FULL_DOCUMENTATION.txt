PART 1 — PROJECT OVERVIEW & MOTIVATION
================================================================================

1.1 ABSTRACT
------------
Shadow Trust is a full-stack, production-grade, AI-powered Security Operations
Center (SOC) and Threat Intelligence Platform built around a distributed honeynet
architecture. The system combines low-interaction and medium-interaction honeypots
(Cowrie SSH/Telnet, Dionaea malware capture, Honeytrap multi-port) with a
cloud-native analytics backend, a 30+ page operator dashboard, a 4-stage automated
malware analysis pipeline, a Temporal Graph Neural Network (GNN) behavioral profiler,
MITRE ATT&CK framework integration, AWS cloud orchestration for dynamic VM
provisioning, multi-channel alerting (Email + WhatsApp), and a 6-tier Role-Based
Access Control (RBAC) system.

1.2 MOTIVATION
--------------
Traditional Security Operations Centers (SOCs) rely on reactive, signature-based
intrusion detection systems (IDS) that fail to detect novel or polymorphic threats.
The research gap addressed by Shadow Trust is:

  (a) Passive vs. Active Intelligence: Honeypots traditionally log attacks but
      don't analyze them in real-time. Shadow Trust closes this gap by running an
      AI classification engine, session correlator, and malware analyzer
      concurrently with event ingestion.

  (b) Fragmented Tooling: Analysts typically juggle 8-12 disparate tools
      (Wireshark, VirusTotal, MITRE Navigator, sandbox, GeoIP, etc.). Shadow Trust
      unifies all of these into a single operator console.

  (c) Lack of Mobile Threat Coverage: Existing SOC platforms focus on network-level
      and Windows binary analysis. Shadow Trust adds a dedicated APK (Android
      Package) intelligence engine.

  (d) Edge-Cloud Architecture Gap: Most honeypots either store data purely locally
      or require constant cloud connectivity. Shadow Trust implements an
      "edge-first" SQLite architecture with eventual-consistency S3 sync — allowing
      offline honeypot operation.

5.1 AI ATTACK CLASSIFICATION ENGINE
--------------------------------------
File   : backend/ai_engine/classifier.py
Class  : AIEngine
Lines  : 124
Type   : Hybrid (Signature-based + Behavioral/Stateful)

DESCRIPTION:
  The AIEngine is the core threat detection algorithm of Shadow Trust. It operates
  in two phases:
    Phase 1 — Signature-based analysis using regular expressions against payloads.
    Phase 2 — Stateful behavioral analysis using a sliding-window time-series over
               per-IP event history stored in an in-memory dictionary.

ATTACK TYPES DETECTED:
  1. SQL_INJECTION     — Pattern: SELECT|UNION|INSERT|DELETE|UPDATE|DROP|--|#
  2. XSS               — Pattern: <script|javascript:|onload=|onerror=|alert(
  3. PATH_TRAVERSAL    — Pattern: ../|..\|/etc/passwd|c:\windows
  4. COMMAND_INJECTION — Pattern: ;|\|`|$( |&&
  5. SSH_BRUTE_FORCE   — Pattern: Failed password|Invalid user|authentication failure
  6. NMAP_SCAN         — Behavioral: 5+ distinct ports in 10 seconds
  7. DDOS              — Behavioral: 20+ requests in 5 seconds
  8. BRUTE_FORCE       — Behavioral: 5+ auth failures in 60 seconds

SEVERITY MAPPING:
  CRITICAL : SQL_INJECTION, COMMAND_INJECTION, DDOS
  HIGH     : XSS, SSH_BRUTE_FORCE, NMAP_SCAN, BRUTE_FORCE
  MEDIUM   : PATH_TRAVERSAL
  LOW      : Normal traffic (no match)
  INFO     : NORMAL (no detected attack)

BEHAVIORAL DETECTION THRESHOLDS:
  PORT_SCAN_THRESHOLD  = 5  distinct ports
  PORT_SCAN_WINDOW     = 10 seconds
  DDOS_THRESHOLD       = 20 requests
  DDOS_WINDOW          = 5  seconds
  BRUTE_FORCE_THRESHOLD= 5  failed attempts
  BRUTE_FORCE_WINDOW   = 60 seconds

HISTORY CLEANUP:
  Events older than 60 seconds are pruned from the in-memory history dict.
  If an IP's history becomes empty after pruning, the IP key is deleted to
  prevent unbounded memory growth.

ALGORITHM PSEUDOCODE:
  function analyze_log(payload, ip, port):
    attacks = []
    severity = "LOW"

    // Phase 1: Signature Matching
    for each (attack_name, regex_pattern) in self.rules:
      if regex_pattern matches payload:
        attacks.append(attack_name)
        severity = max(severity, severity_of(attack_name))

    // Phase 2: Behavioral (Stateful)
    if ip is not None:
      self.history[ip].append({timestamp: now, port: port, payload: payload})
      cleanup_old_events(ip, window=60s)

      // Check DDoS
      recent = events in last 5 seconds
      if len(recent) > 20: attacks.append("DDOS")

      // Check Port Scan
      scan_events = events in last 10 seconds
      distinct_ports = unique port values in scan_events
      if len(distinct_ports) > 5: attacks.append("NMAP_SCAN")

      // Check Brute Force
      auth_fails = events in last 60s matching SSH_BRUTE_FORCE pattern
      if len(auth_fails) > 5: attacks.append("BRUTE_FORCE")

    if len(attacks) == 0:
      return {type: "NORMAL", severity: "INFO", mitre: None}

    primary = attacks[-1]  // Behavioral overrides signature
    mitre = map_attack_to_mitre(primary)
    return {type: primary, severity: severity, mitre: mitre}

              "XSS": r"(?i)(<script|javascript:|onload=|onerror=|alert\(|document\.cookie)",
              "PATH_TRAVERSAL": r"(?i)(\.\./|\.\.\\|/etc/passwd|c:\\windows)",
              "COMMAND_INJECTION": r"(?i)(;|\||`|\$\(|\&\&)",
              "SSH_BRUTE_FORCE": r"(?i)(Failed password|Invalid user|authentication failure)"
          }
          self.history = defaultdict(list)
          self.PORT_SCAN_THRESHOLD = 5
          self.PORT_SCAN_WINDOW = 10
          self.DDOS_THRESHOLD = 20
          self.DDOS_WINDOW = 5
          self.BRUTE_FORCE_THRESHOLD = 5
          self.BRUTE_FORCE_WINDOW = 60

      def _cleanup_history(self, ip):
          now = datetime.now()
          self.history[ip] = [e for e in self.history[ip]
                              if (now - e["timestamp"]).total_seconds() < self.BRUTE_FORCE_WINDOW]
          if not self.history[ip]:
              del self.history[ip]

      def _detect_behavioral(self, ip):
          if ip not in self.history: return None
          events = self.history[ip]
          if not events: return None
          now = datetime.now()

          # DDoS
          recent = [e for e in events if (now - e["timestamp"]).total_seconds() < self.DDOS_WINDOW]
          if len(recent) > self.DDOS_THRESHOLD: return "DDOS"

          # Port Scan
          scan_events = [e for e in events if (now - e["timestamp"]).total_seconds() < self.PORT_SCAN_WINDOW]
          distinct_ports = {e["port"] for e in scan_events if e["port"]}
          if len(distinct_ports) > self.PORT_SCAN_THRESHOLD: return "NMAP_SCAN"

          # Brute Force
          auth_fails = [e for e in events
                       if (now - e["timestamp"]).total_seconds() < self.BRUTE_FORCE_WINDOW
                       and re.search(self.rules["SSH_BRUTE_FORCE"], e["payload"])]
          if len(auth_fails) > self.BRUTE_FORCE_THRESHOLD: return "BRUTE_FORCE"

          return None

      def analyze_log(self, payload, ip=None, port=None):
          detected_attacks = []
          severity = "LOW"

          for attack_name, pattern in self.rules.items():
              if re.search(pattern, payload):
                  detected_attacks.append(attack_name)
                  if attack_name in ["SQL_INJECTION", "COMMAND_INJECTION"]: severity = "CRITICAL"
                  elif attack_name in ["XSS", "SSH_BRUTE_FORCE"]: severity = "HIGH"
                  else: severity = "MEDIUM"

          if ip:
              self.history[ip].append({"timestamp": datetime.now(), "port": port, "payload": payload})
              self._cleanup_history(ip)
              behavioral_attack = self._detect_behavioral(ip)
              if behavioral_attack:
                  detected_attacks.append(behavioral_attack)
                  if behavioral_attack == "DDOS": severity = "CRITICAL"
                  elif behavioral_attack in ["NMAP_SCAN", "BRUTE_FORCE"]: severity = "HIGH"

          if not detected_attacks:
              return {"type": "NORMAL", "severity": "INFO", "mitre": None}

          primary_attack = detected_attacks[-1]
          from .mitre_map import map_attack_to_mitre
          mitre_info = map_attack_to_mitre(primary_attack)
          return {"type": primary_attack, "severity": severity, "mitre": mitre_info}

5.11 SHANNON ENTROPY ALGORITHM
---------------------------------
Used in: static_analyzer.py, sandbox_engine.py, url_scan_service.py
Type   : Information theory measure

FORMULA:
  H(X) = -Σ p(xᵢ) * log₂(p(xᵢ))
  where:
    X = byte sequence (for binary) or char sequence (for domain)
    p(xᵢ) = frequency of byte/char xᵢ / total length
    Sum over all unique byte values

IMPLEMENTATION (Python):
  def _calculate_entropy(data: bytes) -> float:
      if not data: return 0.0
      counter = Counter(data)
      entropy = 0.0
      for count in counter.values():
          p = count / len(data)
          entropy -= p * math.log2(p)
      return round(entropy, 3)

INTERPRETATION:
  entropy = 0.0  → Completely uniform data (all same byte)
  entropy = 8.0  → Maximum entropy (perfectly random distribution)
  entropy > 7.2  → Strongly suggests packing or encryption
  entropy > 6.5  → Elevated; possible compression
  entropy > 3.8  → For domains: suggests DGA/randomly generated name

MAX POSSIBLE ENTROPY for a byte array: log₂(256) = 8.0 bits/byte

5.12 RISK SCORING ALGORITHMS
-------------------------------

A. Permission-Based Risk Score (APK):
  score = Σ(4 × critical_permissions)
        + Σ(2 × high_permissions)
        + Σ(1 × medium_permissions)
        + Σ(5 × CRITICAL_dex_findings)
        + Σ(2 × HIGH_dex_findings)
        + Σ(3 × unique_secrets)

B. Behavioral Risk Score (Sandbox):
  score = min(100, indicator_count × 10
                 + (15 if entropy > 6.5)
                 + (12 if packer detected))
  score = max(15, score)

C. URL Risk Score (additive, see 5.8 above)

D. Severity → Risk Level mapping (used across system):
  LOW      : score < 30
  MEDIUM   : 30 ≤ score < 55
  HIGH     : 55 ≤ score < 80
  CRITICAL : score ≥ 80

PART 16 — RESEARCH CONTRIBUTIONS & NOVELTY
================================================================================

16.1 NOVEL CONTRIBUTIONS
--------------------------

1. EDGE-FIRST HONEYNET ARCHITECTURE
   Contribution: Most honeypot systems require constant cloud connectivity or
   store data exclusively on-premise. Shadow Trust introduces an "edge-first"
   SQLite architecture where events are captured locally (offline capable) and
   synced to cloud via eventual consistency. This addresses the challenge of
   deploying honeypots in low-connectivity or air-gapped environments.

2. UNIFIED 4-STAGE MALWARE ANALYSIS PIPELINE
   Contribution: Integration of static analysis + CAPE sandbox + APK engine +
   secret detection into a single API endpoint with standardized output schema.
   This eliminates the need for analysts to use 4+ separate tools.

3. TEMPORAL GNN BEHAVIORAL PROFILER
   Contribution: Novel application of graph neural network principles to
   honeypot telemetry. By representing attack events as temporal graphs
   (IP nodes → Service nodes → Command/File nodes) and computing degree
   centrality, the system derives behavioral signatures and matches them
   to known APT group profiles without requiring a pre-trained model.

4. JUST-IN-TIME CREDENTIAL MANAGEMENT
   Contribution: Integration of one-time-use credential tokens with multi-channel
   delivery (Email + WhatsApp) and complete audit trails into the SOC platform.
   This addresses insider threat and access control in distributed SOC teams.

5. CROSS-PLATFORM BINARY ANALYSIS WITHOUT EXTERNAL TOOLS
   Contribution: The StaticAnalyzer performs deep PE/ELF binary analysis using
   only Python's struct module — no PE parsing libraries (pefile, lief, etc.)
   required. This reduces deployment friction and eliminates dependency chains.

6. SECTOR-BASED THREAT INTELLIGENCE
   Contribution: Division of honeypot network into industry-specific sectors
   (9 sectors) enables cross-sector threat comparison analytics — which industries
   are most targeted, by what attack types, from which geographic regions.

16.2 RESEARCH QUESTIONS ADDRESSED
------------------------------------

Q2: What is the feasibility of zero-external-dependency malware analysis in

    → Addressed by StaticAnalyzer's pure-Python binary parsing.

    → Addressed by TemporalGNNProfiler's graph construction + centrality.

from fastapi import FastAPI
from fastapi.middleware.cors import CORSMiddleware
from app.core.config import settings
from app.api.v1.api import api_router
import asyncio
from contextlib import asynccontextmanager
from app.db.sqlite_db import init_db
from app.services.sync_manager import SyncManager
from app.services.session_engine import SessionEngine
from app.services.aws_telemetry_service import telemetry_engine

@asynccontextmanager
async def lifespan(app: FastAPI):
    print("Initializing Database...")
    await init_db()
    sync_task = asyncio.create_task(background_sync_loop())
    session_engine_task = asyncio.create_task(background_session_loop())
    telemetry_task = asyncio.create_task(telemetry_engine.run_pipeline())
    yield
    sync_task.cancel()
    session_engine_task.cancel()
    telemetry_engine.is_running = False
    telemetry_task.cancel()

async def background_sync_loop():
    while True:
        try:
            await SyncManager.run_sync_cycle()
        except Exception as e:
            print(f"Background Sync Error: {e}")
        await asyncio.sleep(10)

async def background_session_loop():
    while True:
        try:
            await SessionEngine.process_unmapped_events()
        except Exception as e:
            print(f"Session Engine Error: {e}")
        await asyncio.sleep(60)

app = FastAPI(
    title="Shadow Trust AI Honeypot",
    description="AI Powered Threat Intelligence Platform",
    version="2.0.0",
    openapi_url=f"{settings.API_V1_STR}/openapi.json",
    lifespan=lifespan
)

app.add_middleware(
    CORSMiddleware,
    allow_origins=["*"],
    allow_credentials=True,
    allow_methods=["*"],
    allow_headers=["*"],
)

app.include_router(api_router, prefix=settings.API_V1_STR)
